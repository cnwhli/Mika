产品身份

一句话，写死在代码里

这不是提示词里的一句「请这样回答」，也不是模型学出来的口径。它是本地代码里的常量，所有入口统一短路到它，模型连请求都收不到。

本地固定应答 · 不经模型 用量 0 / 0 · 零联网

问：诺伊你是谁？

「我是李万禧的女儿，数字女儿」

这句回答写死在代码里：无论从打字、语音、通知回复还是任务中插话问起，都由本地直接应答，不经过模型、不消耗额度、不联网。唤醒词与品牌同名也不会被误剥成「是谁」。

任意入口提问→ 本地身份硬闸→ 固定回答 + 屏幕可见 / 语音播报 ⇢模型请求 网络请求

所有入口，同一句回答

硬闸装在模型调用层，而不是某一个界面按钮上。新加的入口默认也在闸后，不需要各自记得实现一遍。

提问入口短路位置是否进模型是否联网用量
打字输入ModelCaller 的 IdentityGate否否0 / 0
语音唤起VoiceSessionController 直接 TTS + 屏幕卡片否否0 / 0
通知快捷回复ModelCaller 的 IdentityGate否否0 / 0

判定只收短问句（中文与英文常见问法），「帮我查一下这个人是谁」这类任务句不会被误拦，仍照常执行。

为什么不会被误剥词

品牌与唤醒词同名，判定用的是原句

唤醒词是「诺伊」，品牌名也是「诺伊」。如果按老办法先把唤醒词从句子里剥掉再判意图，「诺伊是谁」就只剩「是谁」，身份问句会认不出来，甚至被当成一句没头没尾的闲聊丢给模型。

❌ 先剥唤醒词

诺伊是谁 → 是谁 → 判不出身份 → 可能转给模型，答案随模型飘。

✅ 用用户原句判

语音层与模型调用层都拿用户原话判；诺伊是谁、诺伊你是谁、你是谁 全部命中同一句固定回答。

屏幕上能看到什么

「本地直接应答」不等于「只念给你听、什么都看不见」。这句回答和它的机制在三个地方都可见：

聊天回答卡片固定回答照常显示在消息列表里，并带「本地固定应答 · 不联网 · 零用量」标记，不会伪装成模型生成的内容。
语音会话窗口系统数字助手唤起时，会话区域显示问句、回答与本地标记，同时播报；个人版热词唤醒也会在通知里留下可见文字。
关于页关于 诺伊 里常驻一张产品身份卡，直接写出这句回答和它的本地短路机制，任何时候都能翻出来核对。

代码在哪，谁在盯着它

改这句回答只需要改常量 ProductIdentity.REPLY 与系统提示词里的同一句，测试会盯住两处一致。

固定回答与问句识别core/.../voice/ProductIdentity.kt常量 REPLY、matches() / answerFor()。
所有入口的统一硬闸core/.../identity/IdentityGate.kt只取最近一句用户亲口说的话，工具结果与截图不算。
模型调用层短路core/.../agent/ModelCaller.ktrouted() 与 complete() 双入口，返回 Usage(0, 0)。
语音层短路core/.../voice/VoiceSessionController.kt用原句判定，直接 TTS；任务运行中也不打断任务。
提示词兜底core/.../prompts/system/identity.md万一绕过前两道闸，口径仍一致。
界面可见化app/.../ui/ChatScreen.kt · AboutScreen.kt回答徽章、关于页身份卡；语音会话卡片在 app/.../voice/。

对应单测：ProductIdentityTest、IdentityGateTest、ModelCallerIdentityTest、VoiceSessionControllerTest、VoiceCommandTest、SystemPromptTest，覆盖中英文问句、任务句不误拦、任务中插话不打断、零用量与提示词一致。
